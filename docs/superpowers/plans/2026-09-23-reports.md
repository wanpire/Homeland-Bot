# Reports Implementation Plan (Epic Part 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One reporting screen covering signups, accounts, revenue, trial conversion and top plans, over the same periods Financial uses.

**Architecture:** Four new query functions beside Part 2's in `app/services/reporting.py`, and a thin router that renders them. Nothing about periods or revenue is redefined.

**Tech Stack:** Python 3.12, aiogram 3.x, SQLAlchemy 2.0 async, pytest in the isolated Docker stack.

**Spec:** `docs/superpowers/specs/2026-09-23-reports-design.md`

## Global Constraints

- Reuse `PERIODS`, `period_start` and `revenue_summary`; do not restate a period boundary or a definition of revenue.
- **Never read `VPNUser.expires_at`** - nothing writes it. Live status comes from `get_service_status`, capped and reported as a sample.
- Admin text stays English, never `t()`. Sales and above; a refused tap says so.
- Registered before `admin_fallback`; thin handlers, async only, type hints.
- Run the suite with `make test` or the sync-and-run fallback.

## Task 1: The four query functions

**Interfaces:** `signup_count(session, *, period) -> tuple[int, int]` (period, all time); `account_breakdown(session, client, *, limit=20) -> AccountBreakdown`; `trial_conversion(session, *, period) -> TrialConversion`; `top_plans(session, *, period, limit=5) -> list[PlanSales]`.

- [ ] **Step 1: Write the failing tests** covering: signups counted per period and all time; each live status tallied and `checked`/`total` reported when sampling; an IBSng error tallied as unknown rather than raising; a trial user who paid later counted as converted; zero trials giving 0% not a ZeroDivisionError; top plans ranked by paid orders only.
- [ ] **Step 2: Run to verify it fails.**
- [ ] **Step 3: Write the functions** beside the Part 2 ones, reusing `period_start` and `_effective_date`.
